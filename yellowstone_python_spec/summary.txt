5. Generate and connect the replays
Run the Python tests
From the folder containing both Python modules:

bash

python -m unittest discover -s tests -p "test_river_*.py" -v
Generate a control replay
Use the actual local paths to your Godot data:

bash

python river_world.py \
  --world ../../yellowstone_midway/data/world.json \
  --ecosystem ../../yellowstone_midway/data/ecosystem.json \
  --out derived/firehole_control.json
Generate the warming intervention
bash

python river_world.py \
  --world ../../yellowstone_midway/data/world.json \
  --ecosystem ../../yellowstone_midway/data/ecosystem.json \
  --pulse-source excelsior_aggregate_outflow \
  --pulse-start 300 \
  --pulse-end 900 \
  --pulse-delta-c 18 \
  --out derived/firehole_pulse.json
This changes only the river-entry temperature of the existing source. It does not remove other sources or add another copy of Excelsior discharge.

Enable playback in Godot
Copy the generated JSON into the Godot project:
text

   data/firehole_control.json
   data/firehole_pulse.json
Save the two GDScripts underscripts/.
In a duplicate study scene, replace the ecosystem node’s attached script withpython_river_replay.gd.
Set itsreplay_path to:
text

   res://data/firehole_pulse.json
Apply the small fish-query change above.
Add the optional overlay node.
Start the scene and press H.
The pulse begins after 300 physical seconds and ends after 900. The default replay covers two physical hours. Those are scenario settings, not project deadlines.

For a shorter numerical smoke test:

bash

python river_world.py \
  --world world.json \
  --ecosystem ecosystem.json \
  --duration 120 \
  --out derived/firehole_smoke.json
Do not use the existingpublish.py for these artifacts yet. It does not know about this replay schema.
