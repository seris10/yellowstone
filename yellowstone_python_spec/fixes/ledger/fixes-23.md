## Cross-project issues
- `simulation.start_utc` can propagate (per `resolve_replay_start_epoch`), but the current build on disk fell through to `system_clock_date`; the manifest records neither the start timestamp nor the `simulation_time_source`.
- `BUILD.json` records `deps["terrain.f32"]` as a bare sha256, so fixes-22 item 11 (path-aware match) cannot be satisfied without changing this schema in `build.py:180-187` as well.
- Validators `registry_errors`, `validate_contract`, and `validate_inventory` exist in the package but are never run; the build writes the contracts as sidecars and treats their serialization as validation.

## Scientific validity flags
- Overland flow produces a runoff field that is never routed to the river; `boundary_m3s = baseflow_m3s + runoff_m3_s` only includes the scalar snow increment, so the published hydrology artifact and the river boundary disagree.
- Legacy mixing chain uses one scalar `air0` while the replay uses a reconstructed diurnal curve; downstream artifacts (fish, foodweb, bridge temperature) mix outputs produced from two different forcings.
- Open-Meteo bundle is treated as `measured_remote_not_calibrated`; it is model-reanalysis output, so claims that lean on `met_bundle: true` can inherit "measured" status without any local observation.
- `rain_mm_h` fallback copies a daily depth into an hourly rate, inflating configured rainfall by ~24x whenever the config omits `overland.rain_mm_h`.
