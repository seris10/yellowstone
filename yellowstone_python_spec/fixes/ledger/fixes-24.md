## Cross-project issues
- `coupling_check.json` is not a sidecar yet; `build.py:1027-1031` still writes `coupling.json` holding the `EXCHANGES` contract, so a downstream consumer looking for a validation record finds only the declaration.
- Contract item `snow_runoff_discharge` says the increment reaches both hydrology models, but the replay receives `boundary_m3s` through `_prepare_replay_ecosystem`, so updating the wording also requires alignment with `build.py:208-209, 441-453`.
- `equations.py` has no reverse pointer into `fixes-17-surface_flux` work (damped Newton), so updating item 16 requires knowledge of `replay/surface_flux.py` beyond this doc.

## Scientific validity flags
- Lateral volume check compares `sum(flow)*duration` to recorded `lateral_input_m3`; if the solver begins exposing scheduled sources, this invariant will silently false-fail or false-pass depending on the schedule.
- Cross-family tolerance is a hardcoded 2.0 degC regardless of calibration RMSE, surface linearization error, or whether reach and replay windows overlap in time.
- Dimensionally mixed documentation (M01 "enthalpy" with no rho*cp factor) risks downstream reviewers inferring the wrong units from the inventory.
- `_landscape_profile` sorts every `s_m` cell including off-channel pockets; a pocket at the same chainage as a solver cell can flip the interpolated reach temperature by several degrees without triggering a failure.
