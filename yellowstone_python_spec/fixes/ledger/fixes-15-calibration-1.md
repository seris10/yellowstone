## Cross-project issues
- param_registry.py:21-77 declares `manning_n` and `dispersion_m2_s` with fixed status; a staged calibrator would need to update those entries, which the doc did not consider.
- claims.py:48-50 already names `derived/firehole_obs.json:holdout` and `derived/firehole_obs_locked_final.json` as evaluation datasets; the doc's claim about train/holdout/locked discipline is partly realized through claims.py, not through calibrate.py.
- The doc assumes a `River` that accepts time-varying boundary discharge (stage A). `River.__init__` fixes face flow at construction (river_transport.py:410-467); any staged hydraulic calibration would require the extension described in fixes-15.2.

## Scientific validity flags
- replay/calibrate.py:369 reduces measured upstream discharge to a scalar mean before forcing (`mean_q = math.fsum(up_q)/len(up_q)`); regime_scores_by_flow then scores residuals by observed flow terciles the solver never saw, which is misleading.
- replay/surface_flux.py:41 hard-codes `SITE_PRESSURE_KPA = 77.8` but microclimate.py:11 derives ~77.4 from the barometric formula; the two drift ~0.4 kPa.
- replay/surface_flux.py:70-75 uses `(1 + 0.22*cloud**2)` cloud longwave factor as an illustrative empirical form; it is used in the fit as if validated.
- replay/calibrate.py:317-318 collapses c_h and c_e to a single multiplier; this is defensible for sparse data but is not labeled as an identifiability constraint in the output schema.
