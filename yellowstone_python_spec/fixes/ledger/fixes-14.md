## Cross-project issues
- yellowstone_midway/scripts/world.gd now preloads AtmosphereController and WeatherSnapshotReader, uses PhysicalSkyMaterial, drives simulation epoch and delegates sky/sun to the controller (world.gd:4-5,20,80-104,397-422). The three atmosphere scripts and the cloud shader were copied into yellowstone_midway/scripts and yellowstone_midway/shaders so Godot resolves them under res://.
- yellowstone_python has no producer for user://weather/latest.json; the reader is wired to consume a file nothing in the Python package writes.
- The Python /api/weather endpoint keeps the pre-fix flat shape, so the consumer's dual-path code is the only reason the HTTP side works at all.

## Scientific validity flags
- NOAA fallback solar routine in yellowstone_atmosphere.gd:647-661 reuses the input hour as mean solar time (hour_angle = minutes/4 - 180) after adding the equation of time, so civil-time inputs are off by up to ~16 minutes without a Python solar override.
- Snow fraction in llm_backend.py:293-295 uses `t_c - 2.5*(1-rh)` with the night air temperature, not a wet-bulb computation, despite the doc note; the renderer treats whatever arrives as truth.
- Cloud shell altitude lives in the player-local frame when cloud_world_altitude_mode is false (yellowstone_atmosphere.gd:500), so cloud base above sea level moves with the camera and does not represent a fixed atmospheric layer.
