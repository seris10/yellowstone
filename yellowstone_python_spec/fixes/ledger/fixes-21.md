## Cross-project issues
- Doc targets three fetchers in isolation, but usgs_nwis.py (fixes-20) duplicates the same `_parse_iso_epoch`/`_safe_float`/qualifier-dropping and non-atomic write pattern; a shared observation_io.py (item 5) must land before any fetcher fix becomes durable.
- The frozen six-column schema (fetch_met_forcing.py:24-29) is pinned by consumer indices in replay/calibrate.py:369-373 (`r[1]..r[5]`); any v2 schema that renames columns must land in both files simultaneously or the forcing collapses.
- fetch_firehole_obs.py re-exports MET_VARS/OPEN_METEO (one-cycle backcompat note at :49); tests at tests/test_fetch_met_forcing.py:52-96 import `tools.fetch_firehole_obs as f` and `tools.fetch_met_forcing as mf`, so the re-export cleanup must stay source-compatible for those tests.

## Scientific validity flags
- Naive datetime.fromisoformat in fetch_firehole_obs.py:67 and the `.replace(tzinfo=UTC)` misuse in fetch_met_forcing.py:50-52 systematically mis-stamp observations whenever the provider returns an offset-aware ISO string (Open-Meteo responses include `+00:00`), which perturbs calibration-grid alignment in replay/calibrate.py:_fit_forcing_arrays.
- SNOTEL PRCP semantics (daily accumulation increment, fetch_snotel_obs.py:144-146 as prose) are not expressed as machine metadata; any downstream snow mass balance that treats PRCP as cumulative without the brief check will double-count or lose precipitation.
- Open-Meteo values are integrated into the bundle as "measured_remote_not_calibrated" (fetch_firehole_obs.py:142) with the role note only in prose; a reader that uses `met.hourly` as observational air temperature will promote NWP forcing to observation.
- No fetcher embeds a content hash on the written JSON; file-based reproducibility rests on fetched_at_utc alone, which does not distinguish two separate retrievals that returned identical content.
