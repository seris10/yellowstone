## Cross-project issues
- fish-6/fish-8 (chainage-based membership) would ripple into `build.py` and `check_cross_family` (coupling.py:294-353), which rely on the current z-window + membership output; a refactor must update both callers.
- flora-9 (CLI dispatch) depends on module-level import ordering: with flora-8 unresolved, importing or dispatching `forest_infill`/`grove_planting`/`deck_viewshed_groves` from `main()` would execute them during module load path.
- flora-10 (shared constraints) requires the REGIONS consumer `propose_plantings_reviewed` to accept an expanded exclusion test; current `excluded` lambda contract (x, z) -> bool fits, but the review stage also has its own `review()` gate.
- `canopy_census.load_pool_rings` and gen_flora's shells share the same `world.json/pools` source but reach it through different code paths; any geometry refactor must touch both.

## Scientific validity flags
- `suitability` can emit negative values (fish.py:170 clamps top but not bottom), so downstream rankings in `select_refuge` compare mixed-sign utilities as if they were commensurate scores.
- Thermal weights sum to 1.8 while positive terms sum to 0.7 (fish.py:11); the resulting `U` is dominated by penalties and the ceiling at 1 is rarely binding.
- `reach_membership` still assigns points by z-window (fish.py:231-236), which misclassifies looping or U-shaped reaches regardless of fish-6 validation.
- `grove_planting` samples canopy brightness at the cell corner (gen_flora.py:528-531), so individual placements inherit the top-left pixel's light value rather than their own.
- `_BARREN = (None,)` is still at module scope (gen_flora.py:194); any future function that reads it directly will see the stale global instead of the per-call state.
