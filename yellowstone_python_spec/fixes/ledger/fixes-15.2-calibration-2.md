## Cross-project issues
- The item "Extend `River` to accept scheduled boundary discharge" (doc section "Better correction") is a river_transport.py change; `River.__init__` fixes `boundary_m3_s` as a scalar at river_transport.py:410, and `face_flow_m3_s` is a tuple set once at river_transport.py:463. Any staged hydraulic calibration (fixes-15 stage A) depends on this.
- Doc section "How to calibrate radiation corrections" presumes BudgetParams exposes `shortwave_multiplier` and `longwave_bias_w_m2`; the live surface_flux.py has no such fields (surface_flux.py:111-134). Adding them in calibrate.py alone would fail at the solver boundary.
- `regime_scores_by_flow` (calibrate.py:178) scores by observed-flow terciles while the model saw only `mean_q`; the doc's warning that the regime analysis is misleading is not reflected in a code change.

## Scientific validity flags
- Grid champion is picked by train_rmse alone (calibrate.py:533); a bad-budget candidate can still win and only gets flagged after selection (calibrate.py:540).
- `c_mult` scales c_h and c_e identically (calibrate.py:317-318); the labeling notes this but there is no explicit identifiability check.
- `ivp_crosscheck` compares RK45 against backward-Euler without an automatic timestep-halving sweep; a single run cannot distinguish timestep error from physics error.
- `_fit_forcing_arrays` collapses measured discharge to its mean before the solver (calibrate.py:369); this is the identifiability issue called out in the doc and remains in the code with metadata only.
