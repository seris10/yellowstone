## Cross-project issues
- Fixes-20 says the raw bundle should feed calibrate via `assemble_firehole_obs.py`, but the live calibrate.py imports `firehole_obs.v1` (replay/calibrate.py:354-356) and reads `bundle["sites"][site]["series"]["temperature_c"]`; neither live usgs_nwis nor the Downloads normalized schema produce that bundle without the proposed assembler.
- Doc proposes `channel_geometry.py` get a per-feature applicability map; today channel_geometry.py:166-167 reads `m.get("area_sqft")/m.get("width_ft")` directly off a list of raw dict rows, so any normalizer that re-nests `measurements` into `{records, units, status, quality}` breaks `_usgs_mean_depth` even though the raw rows are preserved (confirmed in Downloads normalize_site_result lines 758-763).

## Scientific validity flags
- discharge_iv is written in ft3/s with no unit label (tools/usgs_nwis.py:197); any downstream reader that assumes m3/s silently uses values 35x too large.
- temperature_range>20 as a rejection rule (used downstream in fetch_yellowstone_tributaries.py:331-333) is not sound; the live usgs_nwis emits no complementary coverage/qualifier metadata, so a quiet-but-wrong series passes with no challenge.
