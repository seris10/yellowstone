This `calibrate.py` is the layer that **estimates parameters**, while the damped Newton change is a **numerical method used inside each forward model run**.

The relationship is:

```text
calibrate.py
    proposes Q_lat, T_lat, c_mult, geometry, etc.
        ↓
build_fit_river()
        ↓
River(..., surface_budget=...)
        ↓
damped Newton solves each nonlinear timestep
        ↓
modeled downstream temperature
        ↓
calibrate.py scores RMSE/bias/holdout performance
```

Damped Newton improves the forward simulation used by calibration. It does **not** itself estimate `c_mult`, `Q_lat`, or `T_lat`.

# Important identifiability limitation

This fit has three adjustable parameters:

```python
Q_lat
T_lat
c_mult
```

That is a reasonable restrained calibration. It avoids trying to estimate too many correlated variables from one downstream temperature series.

But `Q_lat` and `T_lat` can compensate for each other. For example:

```text
higher flow × cooler temperature
```

may produce a similar thermal effect to:

```text
lower flow × warmer temperature
```

Likewise, `c_mult` can compensate for errors in:

- surface area;
- volume;
- radiation;
- air temperature;
- humidity;
- channel depth.

Therefore, the output should be interpreted as:

```text
effective single-reach fitted parameters
```

not uniquely measured physical properties.

The script’s status label is appropriately cautious:

```python
"fitted_not_validated_single_window"
```

# Critical issue: this fit currently discards varying upstream discharge

In `_fit_forcing_arrays()`:

```python
up_q = interp_series(up["discharge_m3_s"], grid)
mean_q = math.fsum(up_q) / len(up_q)
```

Then `run_fit_forward()` uses:

```python
boundary_q_m3_s=arrays["mean_q"]
```

So despite loading the measured upstream discharge series, the simulation uses a constant mean discharge.

That is a major modeling simplification. It means:

- measured discharge variation does not affect the forward model;
- travel time is fixed;
- advective export is fixed;
- lateral-flow effects are not represented under changing upstream flow;
- `regime_scores_by_flow()` evaluates model residuals by observed flow regime even though the model did not use that flow variation.

This can make the regime analysis misleading.

## Minimum correction

If the current `River` only supports constant boundary flow, explicitly rename the result:

```python
"boundary_q_m3_s": arrays["mean_q"],
"boundary_q_source": "mean_of_measured_upstream_series",
"discharge_variability_ignored": True,
```

and document:

```python
"boundary_discharge_mode": (
    "constant mean upstream discharge; measured temporal variation "
    "not passed to the solver"
)
```

## Better correction

Extend `River` to accept scheduled boundary discharge:

```python
boundary_m3_s: Any
```

and parse it as:

```python
self.boundary_m3_s = Series.parse(boundary_m3_s)
```

Then face flows cannot remain fixed at initialization. They must be recomputed at each forcing interval:

```python
boundary_q = self.boundary_m3_s.at(time_s)
```

The advective coefficients and outlet flow should then be time-dependent.

That is a larger change, because it affects:

- `_system()`;
- `_advance_to()`;
- `face_flow_m3_s`;
- geometry records;
- water-volume accounting;
- travel-time diagnostics;
- lateral-source propagation.

Do not simply replace the mean with a `Series` without changing those pieces.

```python
surface_area_m2 = area_m2
```

```python
"effective_geometry": {
```

# Damped Newton changes `ivp_crosscheck()`

The docstring says:

```text
RK45 on the NONLINEAR surface budget vs River's backward-Euler on
step-frozen linearized forcing
```

After damped Newton, this becomes inaccurate. The River solver is no longer just one-pass linearized if the explicit budget is active.

Update the docstring:

```python
"""Independent RK45 integration of the lumped cell versus River.

The RK45 path integrates the nonlinear surface-budget ODE directly.
The River path uses backward Euler with damped Newton iteration to solve
the nonlinear implicit surface budget at each step.

Differences measure timestep and integration-method error, not simply
linearization error. Repeat with smaller dt_s and verify convergence.
"""
```

Also report the River iteration diagnostics:

```python
budget = river.budget()

return {
    "n_steps": n + 1,
    "rk_nfev": int(solution.nfev),
    "euler_dt_s": step,
    "max_abs_diff_c": float(np.max(diff)),
    "mean_abs_diff_c": float(np.mean(diff)),
    "argmax_s": float(int(np.argmax(diff)) * dt_s),
    "rk_final_c": float(rk_t[-1]),
    "euler_final_c": float(euler_t[-1]),
    "budget_ok": (
        budget["heat_relative_residual"] <= 1e-5
    ),
    "surface_solver": {
        "max_iterations_used": budget[
            "max_surface_iterations_used"
        ],
        "iteration_failures": budget[
            "surface_iteration_failures"
        ],
        "max_surface_linearization_error_w": budget[
            "max_surface_linearization_error_w"
        ],
    },
}
```

## Important limitation in the RK45 comparison

The RK45 implementation uses:

```python
flux = flux_at(temp, met, params)["net"]
```

which is a true nonlinear explicit RHS.

The River path uses implicit backward Euler. Even after Newton convergence, the two methods will differ because:

- RK45 is higher-order and adaptive;
- backward Euler is first-order;
- forcing is piecewise constant;
- the River solve samples the forcing at the step start;
- RK45 may evaluate within a forcing interval.

That difference is expected. The correct test is timestep convergence:

```text
dt = 900 s
dt = 450 s
dt = 225 s
```

The difference should decrease systematically.

The script already has:

```python
train
holdout
```

and compares:


That is good practice.

However, the grid ranking is based only on:

```python
train_rmse
```

A candidate with a slightly lower RMSE but a large bias or failed budget can become champion.

Use a validity filter before ranking:

```python
candidate_forward = forward(q, t, c)

if not candidate_forward["budget_ok"]:
```

Also record:

```python
train_bias
holdout_bias
max_abs
```

```python
if abs(tr["bias"]) > max_allowed_bias:
```

```python
score = (

    + 0.1 * nonlinear_iteration_penalty

```

Keep the raw metrics as the primary results; use composite scores only for selection and document them.

# Fix `check_continuity()` duplicate timestamps

This function sorts times but does not reject duplicates:

```python
times = sorted(...)
intervals = [b - a for a, b in zip(times, times[1:])]
```

A duplicate timestamp creates a zero interval and can distort the nominal interval.

Add:

```python
if any(
    later <= earlier
    for earlier, later in zip(times, times[1:])
):
    raise ValueError(
        f"{label}: timestamps must be strictly increasing"
    )
```

If duplicate observations should be merged, do that explicitly before continuity checking.

```python
if any(
```

# Bottom line

This script is already a useful calibration framework, but its roles should be distinguished:

## `calibrate.py` estimates

```text
effective lateral flow
effective lateral temperature
common turbulent-transfer multiplier
```

## `river_transport.py` numerically solves

```text
advection
dispersion
mixing
surface heat exchange
nonlinear explicit budget
```

## Damped Newton improves

```text
the accuracy and consistency of each forward simulation
```

It does not automatically improve parameter identifiability.

The highest-priority changes are:

1. Use damped Newton explicitly in `build_fit_river()`.
2. Update `ivp_crosscheck()` documentation and diagnostics.
3. Add `additional_heat_flux_j` and iteration fields to `run_fit_forward()`.
4. Reject failed Newton candidates during fitting.
5. Address the fact that measured discharge is reduced to a constant mean.
6. Record effective geometry and forcing-window provenance.
7. Only add separate `c_h`/`c_e`, radiation, or humidity parameters after adding independent observations or strong priors.
