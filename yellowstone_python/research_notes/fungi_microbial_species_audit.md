# Phase 7: Fungi and Microbial Diversity Audit and Documentation

## Overview
Systematic audit and documentation of all currently unrepresented fungi and microbial species in the Yellowstone Python simulation. Target: 300+ currently unrepresented species beyond the basic ecosystem components currently implemented (150+ fungi species, 150+ microbial species). This Phase 7 establishes the foundation for comprehensive fungi and microbial integration by documenting detailed ecological, ecological engineering, and simulation-relevant parameters for Yellowstone's diverse fungi and microbial communities.

## Current Status Assessment

Based on existing ecosystem components, the following fungi and microbial species are currently represented in the Yellowstone Python simulation:

### Currently Implemented Fungi (Very Limited Representation):
- **Basic ecosystem components:** Currently limited to minimal fungal representations, likely including basic mycorrhizal and saprotrophic functions only.

### Currently Implemented Microbial Species (Very Limited Representation):
- **Basic ecosystem components:** Currently limited to basic bacterial and microbial processes, with minimal Yellowstone-specific representation.

**Total currently represented:** Minimal fungi and microbial species in ecosystem modules

## Research Scope

This Phase 7 establishes the foundation for fungi and microbial species integration by documenting:

1. Complete species taxonomy and taxonomic classification within Yellowstone fungi and microbial communities
2. Geographic distribution and Yellowstone habitat requirements across all Yellowstone ecosystems (lake, river, forest, alpine, wetland)
3. Species-specific ecological data: metabolic rates, decomposition rates, symbiotic relationships, Yellowstone ecosystem functions
4. Species interaction data: Yellowstone mycorrhizal networks, Yellowstone microbial food webs, Yellowstone symbiotic relationships
5. Yellowstone-specific ecological roles: Yellowstone nutrient cycling, Yellowstone soil formation, Yellowstone ecosystem engineering
6. Yellowstone-specific ecological significance: Yellowstone keystone species, Yellowstone ecosystem engineers, Yellowstone nutrient cyclers
7. Yellowstone-specific ecological services: Yellowstone decomposition, Yellowstone nitrogen fixation, Yellowstone phosphorus cycling
8. Yellowstone-specific monitoring data from fungal surveys and microbial ecology programs
9. Literature citations with direct URLs to primary research sources, Yellowstone mycological surveys, Yellowstone microbial ecology studies
10. Integration recommendations for ecosystem modules (fungi.py, microbial.py, ecosystem_support.py)

## Simulation Integration Requirements (add to every species profile)

Every fungi / microbial species profile delivered by this audit must include the sections below. They are required for `fungi.py`, `microbial.py`, `ecosystem_support.py` integration per `01_PYTHON_BUILD_SPEC.md` M09 and ecosystem modules.

### A. Simulation Parameter Mapping
State the exact module, file, and variable structures this species feeds:
- Module: `fungi.py` (potential), `microbial.py` (potential), `ecosystem_support.py`.
- Data structures: `derived/<build-id>/substrate_rules.json`, `derived/<build-id>/ecosystem_state.json` (if nutrient-cycling parameters), `species_catalogue.json` expansion.
- Variable mapping: decomposition rate, metabolic rate, symbiotic network parameter (`mycorrhizal_network`, `symbiont_host`), nutrient cycling coefficient (`nitrogen_fixation`, `phosphorus_cycling`, `carbon_sequestration`), `substrate_rules.json` entries (`silica_sinter` vs `travertine` guardrail per `M09`).

### B. Parameter Provenance and Status (binding per AGENTS.md)
For every numerical parameter delivered:
- Declare `run_mode`: `illustrative` (default), `scenario`, `hindcast`, or `observed_replay`. `forecast` builds are refused.
- Label `status`: `illustrative` (coefficients chosen, not calibrated) unless a locked-final evaluation window exists. Both seed claims stay `not_yet_accepted` until then.
- Provide `parameter_provenance`: source filenames, SHA references where applicable, `code_rev`, `units`, `contract_version: "0.1.0"`, `world_id: "yellowstone_midway"`.
- Unknown parameter uncertainty stays `unknown`. Do not invent distributions or ranges where data is missing.
- `M09` guardrail: explicitly state that this module does NOT recolor Midway; it records substrate rules (`siliceous` vs `travertine`) so future basins are not built by "whitening Grand Prismatic."

### C. Validation Criteria (observable behaviors)
State what the simulation must visibly reproduce for this species, per `M09` and ecosystem module acceptance:
- Substrate rules (`substrate_rules.json`) import without affecting Midway bake.
- Decomposition / nutrient-cycling parameters are consistent with thermal ecology (`5-24°C` range) and do not violate `illustrative` contract.
- If mycorrhizal network is modeled: network connections reference existing `vegetation.py` species IDs; no new geometry required.
- Microbial / fungal modules import cleanly (`pytest` green); `audit_provenance` passes with complete `parameter_provenance`.

### D. Thermal, Suitability, and Behavioral Equation Parameters
Provide quantitative parameters compatible with existing / planned simulation functions:
- Decomposition: rate coefficient (per temperature / moisture), substrate type (`wood`, `litter`, `soil`, `thermal_spring`), thermal sensitivity (`Q10` or `T_opt` range).
- Metabolic rate: `metabolic_rate` per biomass or colony size; temperature dependence curve (compatible with `5-24°C` thermal ecology).
- Symbiotic / network: `symbiont_host` mapping (plant species IDs from `species_catalogue.json` / `vegetation.py`), `network_edge_weight`, `competition_factor` with other microbial/fungal species.
- Nutrient cycling: `nitrogen_fixation_rate`, `phosphorus_cycling_rate`, `carbon_sequestration_rate`, `soil_formation_coefficient`.
- Ecosystem engineering (`M09`): `substrate_type` (`silica_sinter` for Midway; `travertine` for Mammoth reference only), `apron_mask` eligibility, `pool_cross_section` parameters if linked to thermal pools.
- Seasonal (`M08`): winter dormancy / spore persistence parameters, `snow_depth_m` effect on soil microbial activity, spring activation trigger (`soil_moisture` / `Tair`).
